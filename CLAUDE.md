# coldest-cfo-live — agent notes

This is the page David actually views (GitHub Pages, public repo). The data path, backend and the full rule set live in `davidstarkk/coldest-cfo-dashboard` — read its `CLAUDE.md` and `LEARNINGS.md` before changing numbers here.

- **NEVER** put new UI logic inline in `index.html`. Add a module + one `<script>` tag (next to `report_quality_module.js`). The workspace mirror sync rewrites `index.html` daily; `scripts/lib/sync_guard.js` (run by `restore-protected-days.yml`) keeps this repo's UI and takes only data from the sync.
- **NEVER** hand-revert a `public mirror sync` commit. If the guard reports `merged_conflicts_kept_ours` / `kept_ours_merge_unparseable` / `took_theirs_page_unsafe`, check that file. Keep `scripts/lib/sync_guard.js` identical to the data repo's `lib/sync_guard.js`.
- **NEVER** invent numbers. `report_quality_module.js` baselines are comparisons only; its rule must match `cfo_backend/report_quality.py` in the data repo (4-week same-weekday median, drops ≥60%, mismatched headline).
- **NEVER** attach a MutationObserver that writes into the subtree it observes; wrap the template render functions instead.
- This repo is public: no credentials, and treat anything committed here as published.
- Run `npm test` (the throttles / protected-days suites had 7 pre-existing failures on 10/28 from Jarvis settings drift).
- **NEVER** let the AD CHANNELS tab (`ad_channels_module.js`) judge a window with missing days: closed `REPORTS` rows have no per-platform spend, so a day that is not in `PARTIAL_REPORTS` and not in `mer_for_manus.json` is a feed gap (`INCOMPLETE n/7`, WoW withheld), not $0. Platform ROAS is platform-reported over the days the platform reported; Meta / Google have spend-only feeds, so their ROAS is `—`. Feeds reach this repo via the data repo's `after-daily-sync` publish step (`LIVE_MIRROR_TOKEN`); do not hand-edit `mer_for_manus.json` here (tests pin it).
- **NEVER** let the 30-day average or the 30-day pies read the last 30 `REPORTS` rows: closed days are sparse (28 September rows + 10/31 + 11/01 spanned Aug 31 – Nov 1). `report_quality_module.js` `rolling()` / `rollingDist()` own the window: 30 calendar days ending at the latest day with data, closed row wins, else the day's partial totals, incomplete partial days excluded and named, missing days listed, nothing zero-filled. `renderChannelPies` is defined after the module tag, so wrap it from `apply()`, not only at boot.
- **NEVER** let the SPEND MIX (MMM) tab (`mmm_module.js`) draw a curve, a marginal ROAS or a recommended budget unless `ads_throttle/mmm_recommendation.json` says `status: recommendation`; `insufficient_data` renders readiness (usable days / 180, per-channel coverage, listed gaps). Both feeds (`ads_throttle/mmm_recommendation.json`, `mmm/results.json`, `mmm/panel_meta.json`) come from the data repo's weekly `mmm-refit.yml` through `lib/publish_live_feeds.sh`; do not hand-edit them here. The tab is advisory next to the Jarvis throttles, never a replacement.
