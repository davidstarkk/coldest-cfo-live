# coldest-cfo-live — agent notes

This is the page David actually views (GitHub Pages, public repo). The data path, backend and the full rule set live in `davidstarkk/coldest-cfo-dashboard` — read its `CLAUDE.md` and `LEARNINGS.md` before changing numbers here.

- **NEVER** put new UI logic inline in `index.html`. Add a module + one `<script>` tag (next to `report_quality_module.js`). The workspace mirror sync rewrites `index.html` daily; `scripts/lib/sync_guard.js` (run by `restore-protected-days.yml`) keeps this repo's UI and takes only data from the sync.
- **NEVER** hand-revert a `public mirror sync` commit. If the guard reports `merged_conflicts_kept_ours` / `kept_ours_merge_unparseable` / `took_theirs_page_unsafe`, check that file. Keep `scripts/lib/sync_guard.js` identical to the data repo's `lib/sync_guard.js`.
- **NEVER** invent numbers. `report_quality_module.js` baselines are comparisons only; its rule must match `cfo_backend/report_quality.py` in the data repo (4-week same-weekday median, drops ≥60%, mismatched headline).
- **NEVER** attach a MutationObserver that writes into the subtree it observes; wrap the template render functions instead.
- This repo is public: no credentials, and treat anything committed here as published.
- Run `npm test` (the throttles / protected-days suites had 7 pre-existing failures on 10/28 from Jarvis settings drift).
- **NEVER** let the AD CHANNELS tab (`ad_channels_module.js`) judge a window with missing days: closed `REPORTS` rows have no per-platform spend, so a day that is not in `PARTIAL_REPORTS`, `advertising_sources_daily.json`, `<channel>_ads_daily.json`, or `mer_for_manus.json` is a feed gap (`INCOMPLETE n/7` / `STALE` / `NO FEED`, WoW withheld), not $0. A published `spend: 0` counts only when the node is measured (`complete` / `closed_day` / `spend_status: verified` / explicit not-live zero); empty `*_ads_data.json` stubs (`pre_launch` / `no_feed`, `daily: []`) are ignored. Do not treat a stale `mer.<channel>.live` flag as LIVE — the badge follows the latest measured day's live flag (paused zeros stay `$0` / `NOT LIVE`). Platform ROAS is that channel's platform-reported value over the days it reported; Meta / Google have spend-only mer nodes, so their ROAS exists only where `performance.platforms` reported, else `—`. Alias keys (`microsoft_ads`, `openai_ads`, `twitter_ads`, …) join onto the canonical id. Feeds reach this repo via the data repo's `after-daily-sync` publish step (`LIVE_MIRROR_TOKEN`); do not hand-edit `mer_for_manus.json` here — tests that need the 10/26 shape read the frozen copy `scripts/fixtures/mer_for_manus_2026-10-26.json`; joint 11/5 CFO fixtures are `scripts/fixtures/cfo_2026_11_05_mer.json` / `cfo_2026_11_05_series.json`. Platform ROAS source order is `PARTIAL_REPORTS[].performance.platforms` (daily, the platform's own spend as denominator; TikTok Shop and website are separate units) → `ad_channel_throttles.series_28d` → `mer_for_manus.json` nodes. The leaderboard / heatmap bands come from `ads_throttle/settings.json` `global` (cut < 2.0x, raise ≥ 2.8x, $200 min 7d spend) — never hard-code them. A `mer_for_manus.json` row newer than both the page's last daily report and `mer.as_of` is today's partial row and never ends the window. Publish `advertising_sources_daily.json` and `<id>_ads_daily.json` next to the page — see `AdChannels.SCHEMA_CONTRACT`. The window selector (YDAY / 7D / 14D / 28D / 60D / 90D) drives **every** panel — pass the window `n` through `channelStats` / `summarize` / `leaderboard` and label from `winShort` / `winLabel`; never hard-code a “7d” label or a 7-day slice in a panel. Tests that read the live `index.html` rows must filter them to the fixture's as_of (the mirror sync moves the page daily).
- **NEVER** let the 30-day average or the 30-day pies read the last 30 `REPORTS` rows: closed days are sparse (28 September rows + 10/31 + 11/01 spanned Aug 31 – Nov 1). `report_quality_module.js` `rolling()` / `rollingDist()` own the window: 30 calendar days ending at the latest day with data, closed row wins, else the day's partial totals, incomplete partial days excluded and named, missing days listed, nothing zero-filled. `renderChannelPies` is defined after the module tag, so wrap it from `apply()`, not only at boot.
- **NEVER** let the SPEND MIX (MMM) tab (`mmm_module.js`) draw a curve, a marginal ROAS or a recommended budget unless `ads_throttle/mmm_recommendation.json` says `status: recommendation`; `insufficient_data` renders readiness (usable days / 180, per-channel coverage, listed gaps). Both feeds (`ads_throttle/mmm_recommendation.json`, `mmm/results.json`, `mmm/panel_meta.json`) come from the data repo's weekly `mmm-refit.yml` through `lib/publish_live_feeds.sh`; do not hand-edit them here. The tab is advisory next to the Jarvis throttles, never a replacement.
- Hidden nav tabs (David 11/03: CMASM, Analytics, Predictive, Scaling, News, ChatGPT / Meta / Google / Bing / Reddit / Snapchat / Pinterest Ads) are hidden by `nav_cleanup_module.js` `HIDDEN` — CSS on `data-tab`, so module-inserted tabs are covered. Panels and data keep running; to bring a tab back, delete its key. Do not delete tab markup or modules.
- **NEVER** commit plaintext subscription dumps. The SUBSCRIPTIONS tab (`subscriptions_module.js`) is the last nav item (`#subscriptions`) and decrypts `subscriptions.enc.json` in the browser (PBKDF2-SHA256 → AES-256-GCM). Ship only the envelope; `subscriptions*.json` plaintext is gitignored. Encrypt with `PASS=… node scripts/encrypt_subscriptions.mjs in.json subscriptions.enc.json`. Cancel marks live in encrypted `localStorage` (same AES key, fresh IV); optional `subscriptions_overrides.enc.json` merges under local marks. Do not hand-edit the live envelope. Tests: `node scripts/test_subscriptions.js`. `?su_example=1` is test-only EXAMPLE DATA.
- **NEVER** compute a verdict, ROAS, feed status or ask in the FEEDS & GROK LOOP tab (`ad_loop_module.js`). It draws `ads_throttle/feed_health.json` + `ads_throttle/cfo_brief.json` exactly as the data repo's `cfo_backend/ad_loop.py` built them (contract: `docs/GROK_LOOP.md` there); a missing day is drawn as missing, never $0, and a faded verdict is what the rule would say for a blocked channel. Both files and `ads_throttle/grok_ack.json` arrive through `lib/publish_live_feeds.sh` — do not hand-edit them here. If the tab says the feeds are not published, the data repo's `LIVE_MIRROR_TOKEN` secret is unset (it was on 11/09: this page's `mer_for_manus.json` sat at 11/04 for five days).
- **NEVER** compute a CAC, a marginal ROAS, a payback, an ordering or a suggestion in the GROWTH tab (`growth_module.js`). It draws `ads_throttle/growth_brief.json` exactly as the data repo's `cfo_backend/growth_loop.py` built it (contract: `docs/GROK_LOOP.md` there). A block whose `status` is not `ok` renders its reason and no number; a holdout factor is shown only for a final read outside its noise. The file arrives through `lib/publish_live_feeds.sh` — do not hand-edit it here. New blocks go through the data repo's `new-brief-field` skill. Tests: `node scripts/test_growth.js`.
- **NEVER** headline `mer_for_manus.json` `mer_7d_pooled` as "the" 7-day MER on the Daily Reports page. That field is Shopify D2C only (Shopify net ÷ D2C ad spend — 1.84x on 11/11 while the company was 3.19x), and David reads the page company-wide. `report_quality_module.js` `merHeader()` / `renderMerHeader()` own the strip: all-channel revenue ÷ all ad spend over 7 calendar days from the same `rolling()` as the 30-day average, DoD / WoW only from full windows, the D2C figure shown beside it under its own label. Page order is as-of bar → the day's card (`dayOnTop()`, titled with the full date, four columns incl. net margin) → compact MER strip → 30-day average. The ADVERTISING FEEDS table (`paid_channels_module.js` `detailBreakdownHtml`) is one row per channel — no `pc-split` sub-rows; a D2C share is noted on the row only when it differs from spend, cash-cost detail is the row tooltip.
